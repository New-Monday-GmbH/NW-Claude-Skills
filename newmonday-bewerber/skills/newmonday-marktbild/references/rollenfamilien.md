# Rollenfamilien

Das Marktbild zählt je Rollenfamilie getrennt. Ein Kandidat bekommt nur die
Lücken der Familien, die in `kandidaten.json` bei ihm stehen – ein Junior
Visual Designer keine Design-System-Governance.

| Rollenfamilie | Ausschreibungen für … |
|---|---|
| `UX/UI` | UX Designer, UI Designer, UX/UI, Product Designer, Interaction Designer, Service Designer für digitale Produkte, UX für eine Plattform (ServiceNow, Dynamics, SAP) |
| `Design Systems` | Design System Designer, Consultant, Lead, Design Ops, Design Engineer mit Schwerpunkt Komponentenbibliothek |
| `Visual` | Visual Designer, Grafik-, Kommunikations-, Brand-, Motion-, Editorial Designer |
| `Research` | UX Researcher, User Researcher, Usability Engineer |

- Eine Ausschreibung bekommt genau **eine** Familie: die, in der die
  Hauptaufgabe liegt. Ein „UX Designer mit Design-System-Erfahrung“ ist
  `UX/UI`; die Design-System-Anforderungen zählen dort.
- Ein Kandidat darf mehrere Familien haben – die, für die er realistisch
  angeboten wird (Matching-Läufe, Rolle im CV).
- Passt eine Ausschreibung in keine Familie, eine neue anlegen und hier
  ergänzen (Pull Request) – nicht in eine falsche Familie zwingen.
